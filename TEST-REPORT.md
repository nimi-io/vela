Deviations from the brief, with the reasons:
- **`garage-init` is a Node script ([`infra/garage-init.mjs`](infra/garage-init.mjs)), not a shell script.** It uses the Garage v2 admin API because the official image has no shell. It runs the same steps as the CLI: layout assign/apply, bucket create, key import, bucket allow.

## Garage compatibility

[`scripts/storage-check.ts`](scripts/storage-check.ts) drives every call in `packages/core/src/storage.ts` through Vela's own client. It passed 21/21 ([output](test-results/storage-check.txt)):
- PutObject

- CopyObject with spaces, unicode and `+` in keys
- ListObjectsV2 across more than 1,000 keys
- DeleteObjects
- presigned PUT and GET through `S3_PUBLIC_ENDPOINT`, including a tampered signature and an expired URL

### Garage quirks

| Quirk | Effect on Vela | Handling |
|---|---|---|
| `response-content-disposition` is ignored on **206** (ranged) responses; on 200 it works | None: MP4 downloads are plain GETs, so the filename still applies | Documented; the check now tests the download the browser actually makes |
| An expired presigned URL returns **400 `InvalidRequest`** ("Date is too old"); AWS and R2 return 403 | None: the URL is still refused | The check accepts 400 or 403 |
| The image has no shell | `garage-init` can't script the CLI | Uses the admin API |
| A browser following a cross-origin 302 sends `Origin: null` | Redirect mode needs bucket CORS GET from `*` | `setup-bucket.mjs --playback-origins` (default `*`, GET/HEAD only; objects still need presigned URLs) |

None of the bugs below were Garage-specific; MinIO would have had the same ones.

## Not fixed: open items and product decisions

**Product decisions**
- **DRM:** a public or signed playback ID can be added to a DRM asset. It can't get a license, but it serves clear thumbnails and GIFs. A clip of a DRM asset defaults to a clear, public copy.
- **Webhook URLs:**
  - They may point at private hosts, and 2,000 characters of the response are readable in the delivery log. The same applies to DRM license and key-registration URLs and simulcast targets.
  - Only asset input URLs are SSRF-guarded.
- **Abuse limits:**
  - The thumbnail cache can be filled without limit (any `time`/`width` on a public ID).
  - `/auth/login` has no rate limit.
- **Admin roles:** an org admin can promote anyone, including themselves, to owner.

**Minor**
- **API responses:**
  - An invalid `?status=` filter returns an empty list.
  - AI endpoints return 201 when no provider is configured; the track then errors.
  - `/data/views` rows are camelCase.
  - The HLS master has no `FRAME-RATE`.
- **Rate limiter:** during a Redis outage, `/v1` requests wait for Redis instead of failing fast.
- **DRM and live:**
  - `KEYFORMAT="identity"` lines in DRM playlists.
  - `health.protocol` reports MediaMTX names (`rtmpConn`).
  - Recordings stay on disk until the 6 h prune (uid mismatch on the shared volume).
- **API:** the API rejects Host headers with uppercase letters.
- **Retries:** `asset.process` has only 2 attempts with a 5 s backoff, so a storage outage longer than that errors assets.
- **UX:** copy/UX items are listed in Agent C's notes (e.g. after re-login you land on the last page; the environments table shows "Development / Development").

**Leftover test data**
- Assets `Yi8t2GrwuxN5LaOQAtypfaJB` and `iLMspDD0VuULbtF01VP7W4Mh` are stuck in `preparing`. They came from runs before fixes 29 and 7, and are left untouched as evidence.
- Asset `D85FqHiSgYAYSRb4Uj93yYmj` shows stale progress (evidence for fix 34).
- About 1.15 GB of old-format leaked dirs remain in the `work` volume.
